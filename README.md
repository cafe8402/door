# AI 업무도구 보안점검 — 웹·AI 소스코드 보안 자가 점검

소스·설정 파일의 로컬 분석과 공개 URL 응답 검사를 지원합니다. 마스킹된 증거·AI 수정 요청문·재검사 비교 결과를 제공합니다. API 키나 외부 AI 계정이 필요하지 않습니다.

## 업무시스템 관리와 임원 보고

홈의 **현황판 열기** 또는 왼쪽 **업무시스템 현황**에서 사용합니다.

1. 시스템 이름, 사용 부서, 책임자와 기본 검사 방식을 등록합니다.
2. 등록된 시스템에서 **첫 검사 시작**을 누릅니다. 일반 검사 시작 화면에서도 연결할 시스템을 고를 수 있습니다. 등록하지 않는 일회성 검사는 이력에 남지 않습니다.
3. 검사가 끝나면 **업무시스템 현황 열기**를 눌러 각 항목에 조치 담당자, 기한, 진행 상태와 메모를 저장합니다. ‘수정 완료’로 표시해도 재검사 전까지 남은 항목입니다.
4. 수정한 자료로 다시 검사하면 같은 규칙·파일을 비교합니다. 빠진 파일이나 실행하지 못한 URL 검사는 ‘확인 못함’으로 유지합니다. 과거 검사와 이전 배포 검토도 이력에서 확인할 수 있습니다.
5. 배포 검토표에 실제 계정 권한·운영 DB·외부 AI 전송·업무 기능을 직접 확인한 내용과 검토 의견을 남깁니다. 새 검사 또는 조치 변경이 생기면 이전 검토는 현재 상태의 검토로 인정하지 않습니다. 검토자 이름은 직접 입력하는 메모이며 인증된 전자결재·배포 승인 기능이 아닙니다.
6. 현황판의 **임원 보고서**에서 독립 HTML 보고서를 내려받습니다. 브라우저에서 열어 인쇄/PDF 저장할 수 있습니다. 작은 등록 목록은 한 장으로 인쇄하도록 구성했으며 목록이 길면 여러 장이 됩니다. **기록 백업**은 관리 데이터 JSON을 내보냅니다.

이 기능은 **현재 브라우저의 localStorage**를 사용합니다. 등록 시스템과 검사 요약(규칙·위치·영향·수정 안내), 담당자·기한·메모·검토 기록만 저장합니다. 업로드한 파일 내용, 코드 증거, AI 요청문, 원문 지문은 저장하지 않습니다. 알려진 비밀값 형식은 마스킹하지만 자유 입력란에 실제 비밀값이나 개인정보를 넣지 마세요. URL의 사용자 정보·검색어·프래그먼트는 보관하지 않습니다. 저장 오류나 손상된 데이터는 오류로 표시하며 기존 기록을 자동으로 덮어쓰지 않습니다.

관리 기록은 새로고침 후에도 남습니다. 브라우저 데이터를 지우면 삭제됩니다. JSON은 외부 보관용 백업이며 현재 자동 복원·서버 동기화·로그인·담당자 알림·전사 시스템 자동 발견은 제공하지 않습니다. 시스템 보관은 되돌릴 수 있고 기록은 유지됩니다. 임원 지표는 보관하지 않은 등록 시스템의 최근 **실제 검사**를 집계하며 기본 예제와 `/__fixtures/` URL 및 가상 API 예제는 제외합니다. 사용자가 수정·복사해 만든 별도 테스트 파일까지 자동 식별하지는 않습니다.

과거 검사와 비교할 때 같은 규칙·파일의 여러 탐지를 하나의 조치 항목으로 묶습니다. 재검사 ‘미검출’은 해당 범위에서 패턴을 다시 찾지 못했다는 뜻입니다. 보안 인증·자동 취약점 수정·실제 침해 성공 확인이 아닙니다.

## 실행

첫 접속과 새로고침에는 **‘AI로 만든 우리 팀의 도구, 회사 자료까지 열어두진 않았나요?’**라는 질문과 점검 버튼이 표시됩니다. 실제 사진·손글씨 분위기를 유지하면서 최근 금융권 사고의 공식 근거 → 점검 결과 설명용 예시 → 배경 통계 → 시작한 마음 → 세 가지 약속으로 이어집니다. 금융권 사례는 금융위원회의 2026년 10월 7일 자료를 사용하며 AI 생성 코드가 사고 원인이라고 단정하지 않습니다. 결과 예시는 실제 검사 결과와 구분합니다. 상단 ‘점검실로’는 점검 홈, ‘내 업무도구 점검하기’와 하단 ‘문 열고 점검하기’는 새 파일 검사로 연결됩니다. 이야기 안의 목차는 페이지를 스크롤하고 검사 상태를 바꾸지 않습니다. 브라우저 뒤로 가기도 지원합니다. 검사 대상 선택 화면에서 파일·주소의 검사 방식, 원문 처리와 용량 안내를 먼저 확인할 수 있습니다.

수치와 사례에는 조사 연도·자료 확인일·원문 링크·해석 범위가 포함됩니다. 실제 침해 신고 통계, 특정 AI 코드 시험 결과, 수정된 취약점 공개 사례를 구분합니다. 실시간 사고 카운터가 아닙니다. 사진·글꼴은 프로젝트에 로컬로 보관하며 출처·라이선스·콘텐츠 근거는 `public/assets/story/CREDITS.md`에 있습니다. 손글씨는 나눔손글씨 펜, 사진은 Unsplash의 Terrillo Walls와 Aleksandr Zaitsev 작품입니다. 이전 별빛 문 디자인은 `ScreenPortal.tsx`와 `design/stitch-security-portal/`에 보존했습니다.

점검 홈도 같은 먹색·종이색·장밋빛과 실제 문 사진을 사용합니다. 같은 페이지에서 이야기를 오갈 때 검사 결과는 유지되고, 새로고침하면 상세 증거는 지워집니다. 업무시스템에 연결한 관리 요약·조치 기록은 유지됩니다.

Windows에서는 **start.cmd**를 더블클릭한 뒤 브라우저에서 http://127.0.0.1:3000 을 여세요. 현재 Codex에 포함된 런타임 또는 설치된 Node.js를 사용합니다. 창을 닫거나 Ctrl+C로 종료합니다. 이미 실행 중이라면 기존 주소를 사용하세요.

다른 환경에서는 Node.js 24 이상을 설치한 뒤 실행합니다.

```sh
npm install
npm run dev
```

기본 접속 주소: http://127.0.0.1:3000 (본인 컴퓨터에서만 접속). 포트가 사용 중이면 기존 서버를 종료해주세요.

## 사용 순서

1. 홈에서 웹사이트 주소 검사 또는 코드 파일 검사를 선택합니다. 검사 이름과 추가 질문은 선택 사항입니다.
2. 본인 소유 또는 검사 권한이 있는 소스 파일·프로젝트 폴더를 선택합니다. 예제로 먼저 시험할 수도 있습니다.
3. 검사 권한을 확인한 뒤 검사 시작을 누릅니다.
4. 탐지 위치·증거·해결 가이드를 확인하고 AI 수정 요청문을 복사합니다. 외부 AI에 전달하기 전에 내용을 검토하세요.
5. 수정한 파일을 **같은 상대 경로**로 다시 제출합니다. 프로젝트 폴더의 최상위 폴더명은 경로에서 제외됩니다.
6. 결과 저장에서 PDF 또는 읽기 쉬운 HTML 보고서로 보관합니다. Markdown·JSON은 다른 형식 메뉴에서 받을 수 있습니다. 상세 코드 증거는 메모리에만 있으며 새로고침하면 지워집니다. 업무시스템에 연결한 검사 요약과 조치 기록은 브라우저에 남습니다.

재검사 비교는 최초 검사 결과가 기준입니다. 미제출·이름이 달라진 파일은 ‘확인 불가’이고, 이전 규칙이 남으면 ‘문제 지속’, 사라지면 ‘패턴 미검출’, 추가 패턴은 ‘새로 발견’입니다. 같은 규칙이 여러 곳에 있으면 동일 코드 문맥을 먼저 대응하고 나머지를 보수적으로 비교합니다. 패턴이 사라져도 기능 보존이나 보안을 보증하지 않습니다.

## 지원 범위

임직원이 사용하는 사내 결재·고객 관리·AI 업무시스템을 위한 첫 코드 점검 도구입니다. 홈은 코드 파일·프로젝트 폴더 검사와 주소 검사 중심으로 정리했으며, 1분 체험·가입 홍보·별도 API 권한 실습 진입을 제거했습니다. 내부 회귀 테스트용 가상 API 서버는 유지하지만 실제 API 권한 검사 기능으로 안내하지 않습니다.

### 이번에 보강한 규칙

- SQL: SELECT/INSERT/UPDATE/DELETE 문자열 결합·JS 보간·Python f-string/%/.format, 위험한 원시 SQL 함수. `$1`·`?` 등 매개변수 사용과 Prisma의 안전한 `$queryRaw` 태그는 구분합니다. AST·변수 추적·저장형 인젝션 전체 분석은 아닙니다.
- CORS: 기존 Express 설정 외에 헤더 설정 함수, JSON 헤더, Python 허용 목록, Django 전체 허용, Nginx 헤더 구문을 추가했습니다. 공개 API의 `*`는 의도된 정책일 수 있어 문맥 검토가 필요합니다.
- RLS: SQL의 DISABLE ROW LEVEL SECURITY, row_security=off, USING(true)·WITH CHECK(true) 정책을 찾습니다. 마이그레이션만 보고 현재 DB의 RLS가 꺼졌거나 없다고 확정하지 않습니다. 테이블 생성문만 있어도 RLS 누락으로 단정하지 않습니다.
- 공개 환경변수: NEXT_PUBLIC_·VITE_의 비밀값을 암시하는 이름·할당을 확인합니다. 실제 번들 노출 여부는 별도 확인합니다.
- 비밀값: Stripe secret/restricted/webhook, Supabase secret/service_role JWT/관리 토큰, Slack 토큰·웹훅, GitLab, npm, SendGrid, Azure Storage, 비밀번호가 포함된 DB URL, JWT 서명 비밀값, Resend를 추가했습니다. 새 형식은 증거·AI 요청문·보고서에서 마스킹합니다.
- Stripe pk_ 및 Supabase anon·publishable 키는 공개용이라는 이유만으로 비밀키로 판정하지 않습니다. 이 키를 사용하는 데이터의 RLS·권한 정책이 안전한지는 별도 문제입니다.

총 37개는 모든 종류의 검사 규칙 수이며, 그중 비밀값 탐지 규칙은 23개입니다. **Gitleaks 전체 규칙·엔트로피 분석·Git 커밋 이력 검사와 동등하지 않습니다.** Gitleaks 결과를 가져오는 기능도 없습니다. 키의 유효성이나 실제 계정 접근은 확인하지 않습니다.

규칙 근거: [Supabase 키 구분](https://supabase.com/docs/guides/getting-started/api-keys), [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Stripe 키](https://docs.stripe.com/keys), [Vite 공개 환경변수](https://vite.dev/guide/env-and-mode), [Next.js 공개 환경변수](https://nextjs.org/docs/app/guides/environment-variables), [OWASP SQL 예방](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html), [Gitleaks 규칙 원본](https://github.com/gitleaks/gitleaks/blob/master/config/gitleaks.toml).

### 업무시스템 테스트 자료와 영상

`demo-data/work-system/vulnerable` 폴더를 코드 검사로 선택한 뒤, `fixed` 폴더를 같은 상대 경로로 재검사하면 수정 전후를 비교할 수 있습니다. 모든 키와 자료는 합성이며 실행용 코드가 아닙니다. SQL 파일을 실제 DB에 실행하지 마세요.

홈의 **이용 안내 영상**에서 완성된 20초 한글 자막 모션그래픽을 바로 재생하고 WebM으로 저장할 수 있습니다. 영상은 public/media/mundansok-work-guide.webm에 포함돼 있으며 음성·외부 전송은 없습니다. Canvas·MediaRecorder로 직접 생성한 설명용 영상입니다. WebM 재생을 지원하는 브라우저를 사용하세요.

- 기존 규칙과 신규 SQL·RLS·공개 환경변수·서비스 비밀값 탐지를 합쳐 37개 정적 패턴 규칙: OpenAI·Anthropic·Google 키, AWS Access Key ID, GitHub 토큰, 개인키, 브라우저 AI 직접 호출, 주민번호, CORS 전체 허용, 동적 코드 실행, 셸 실행, HTML 직접 삽입, TLS 검증 해제, 에이전트 승인 우회.
- UTF-8 텍스트: JS/TS/JSX/TSX, Python, JSON, YAML, ENV, TOML, Markdown, 셸, Go, Java, PHP, C#, SQL 등.
- 파일 용량·전체 용량·파일 개수의 고정 제한은 없습니다. 실제 처리 가능한 양은 브라우저와 기기의 메모리에 따라 달라집니다. 한 파일 3,000건·전체 5,000건 탐지 결과 초과 시 대상을 나눠 검사해야 합니다. 탐지 결과 수 제한은 업로드 용량 제한과 별도입니다.
- 프로젝트 폴더의 node_modules, .git, dist, build, coverage, .next, 가상환경과 지원하지 않는 바이너리는 제외합니다. ZIP은 먼저 압축을 풀어주세요. 오류가 있으면 부분 결과를 정상 결과로 표시하지 않습니다.
- 별도 Web Worker에서 검사하며 검사 중지·화면 이동 시 작업을 종료합니다.
- 파일 내용은 서버로 전송하거나 브라우저 저장소에 보관하지 않습니다. URL 검사에서는 이 컴퓨터의 Node 서버가 대상에 HTTP 요청을 보냅니다. 외부 폰트 요청도 사용하지 않습니다.
- 화면·요청문·보고서는 알려진 키·토큰·주민번호·개인키·일부 명명된 비밀값을 마스킹합니다. 자유 형식 기밀까지 모두 숨기지는 못합니다.

AST/데이터 흐름 분석, 실제 서비스의 인증·인가 우회 검사, 프롬프트 인젝션 공격, CVE 데이터베이스 대조는 구현 범위에 포함되지 않습니다. 주석·예제·테스트의 패턴도 발견할 수 있으며 토큰의 유효성은 확인하지 않습니다. 사전 질문은 수동 검토 안내에 반영됩니다.

## 실제 URL 검사

주소 검사 탭에 검사 권한이 있는 공개 HTTP·HTTPS 주소를 입력합니다. API 키와 외부 AI는 필요 없습니다. 공개 사이트는 80·443 포트만 지원합니다. 대상 사이트에는 GET 요청이 전송됩니다.

- HTTPS 인증서 검증(우회하지 않음), HTTP→HTTPS 이동 여부, 리다이렉트 경로
- 최종 정상 응답의 CSP·HSTS·프레임 제한·nosniff·Referrer-Policy
- 해당 응답이 설정한 쿠키의 Secure·HttpOnly·SameSite(이름과 값은 출력하지 않음)
- HTML의 일부 HTTP 리소스 참조와 서버 버전 정보 노출
- 최종 페이지와 같은 출처 JavaScript 최대 3개에 37개 정적 패턴 규칙 적용
- 수행한 검사·확인 불가·수집 제한을 결과와 Markdown·JSON 보고서에 포함
- 수정된 URL은 최초와 같은 출처(프로토콜·호스트·포트)로 재검사. 수집 실패·401/403 등 비정상 응답·미실행 항목은 해결로 판정하지 않음
- 비교 화면에서 최신 재검사 보고서 및 비교 JSON 저장 가능

### 바로 시험하기

1. 홈 → **예제로 시작** → 권한 확인 → 검사 시작
2. 2개 리소스에서 **7건** 탐지되는지 확인
3. 고친 뒤 다시 검사 → URL 마지막의 vulnerable을 fixed로 변경 → 동일 프로젝트 확인 → 재검사
4. **이번엔 발견 안 됨 7개**, 새 탐지 0개 확인

더미 주소는 http://127.0.0.1:3000/__fixtures/vulnerable 및 /__fixtures/fixed입니다. 실제 HTTP 요청으로 검사합니다. 더미 서버는 HTTP 전용이어서 HTTP·HSTS·인증서 평가를 제외하고 그 사실을 표시합니다. 허용된 더미 경로만 로컬 주소 차단의 예외이며 다른 내부 주소는 허용하지 않습니다.

### 요청 제한과 검사 서버 보호

DNS의 모든 IPv4·IPv6 결과를 검사하고 검증된 IP로 연결을 고정합니다. 로컬·사설·링크 로컬·예약·메타데이터 주소를 차단하고, 리다이렉트마다 재검사합니다. IPv6는 네이티브 글로벌 유니캐스트의 일부만 보수적으로 허용합니다. HTTPS→HTTP 이동은 차단합니다. JavaScript는 리다이렉트 후에도 같은 출처만 허용합니다.

전체 25초, 요청별 6초, DNS 3초, 최대 8회 요청, 리다이렉트 3회, 응답 하나 1MB·전체 3MB로 제한합니다. 압축 응답은 해제하지 않고 확인 불가로 처리합니다. 동시 검사 2개·분당 12회로 제한합니다. 검사 API는 로컬 Host·Origin과 JSON POST·권한 확인을 검증하며, 결과를 저장하거나 임의의 응답 본문을 프록시로 반환하지 않습니다. 화면에서 취소하면 서버 작업도 중지합니다.

로컬 전용 도구입니다. 인터넷에 공개하는 다중 사용자 서비스로 전환하려면 인증, 사용자별 할당량, 네트워크 송신 정책과 격리된 검사 작업자 등 별도 배포 설계가 필요합니다.

### 확인 범위의 한계

JavaScript를 브라우저처럼 실행하거나 모든 페이지·모듈·외부 스크립트를 크롤링하지 않습니다. 쿠키는 최종 응답의 Set-Cookie만 확인하며 기존·로그인 쿠키와 중간 리다이렉트 쿠키는 미검사입니다. 헤더와 코드 규칙은 문맥 검토를 위한 기초 점검이며 전체 보안이나 취약점 악용 가능성을 확정하지 않습니다. JS 파일 이름·경로가 배포 때 바뀌면 이전 리소스는 확인 불가가 될 수 있습니다.

## 배포 빌드로 로컬 실행

npm run build 후 npm start로 실행하면 Vite 개발 서버 없이 같은 화면과 API를 제공합니다. 기본 주소는 http://127.0.0.1:3000 입니다. PORT 환경변수로 포트를 바꿀 수 있습니다. Node.js 24 이상과 소스 디렉터리(server/, src/)를 함께 유지하세요. 정적 dist 파일만 호스팅하면 URL 검사 API는 동작하지 않습니다.

## 화면 사용 안내

점검실 내부는 입구와 이어지는 짙은 남색·금빛·보라색 테마입니다. 홈의 원본 문 이미지는 입구 재방문으로 연결되며, 금빛 점검 버튼은 실제 코드 검사 설정을 엽니다. 입력·진행·결과·수정 안내·재검사·안내/영상/보고서 창에 같은 색상 토큰을 적용했습니다. 경고·추가 확인·성공은 별도 색으로 구분하고, 보고서 인쇄 시에는 밝은 배경의 인쇄용 색상으로 전환됩니다. 독립 HTML·SVG 보고서는 읽기 쉬운 기존 밝은 문서 형식을 유지합니다.

- 왼쪽 홈 또는 상단 홈으로 버튼으로 언제든 홈에 돌아갑니다. 진행 중인 검사는 중지됩니다.
- 홈에서는 최근 결과를 이어서 보거나 저장할 수 있습니다. 새 검사를 선택하면 이전 결과와 입력을 초기화합니다.
- 검사 방법과 필수 입력을 먼저 표시하고 맞춤 질문·기술적인 검사 기록은 접어서 제공합니다.
- 결과는 먼저 확인·추가 확인·참고 순서로 표시합니다. 이는 자동 검사로 찾은 단서이며 실제 취약점 확정을 뜻하지 않습니다.
- 검사 안내는 방법별 카드, 이용 방법은 3단계 안내, 결과 저장은 요약과 보고서 미리보기로 제공합니다.
- PDF로 저장은 브라우저 인쇄창을 사용합니다. 보고서 파일 저장은 외부 자료나 스크립트 없이 열 수 있는 HTML 파일입니다.

### 첫 화면의 빠른 검사 선택

첫 화면의 어두운 반투명 선택 영역에서 **코드 파일 검사**와 **웹사이트 주소 검사**를 바로 선택합니다. 각각 파일 선택과 URL 입력 상태로 연결됩니다. 주요 본문은 16~17px, 본문과 제목은 네이버 마루부리로 표시하며 실제 사진과 짧은 손글씨는 유지합니다. 임원용 기간별 변화 보고서는 아직 제안 단계이며 현재 제공되는 임원 보고서와 구분합니다.

### 글꼴과 서비스명

표시 이름은 **AI 업무도구 보안점검**입니다. 첫 화면·점검실·보고서에 적용하며 기존 브라우저 관리 기록의 저장 키는 그대로 유지합니다. 네이버 공식 마루부리 Regular/SemiBold/Bold를 로컬 제공하며, 저작권과 OFL 전문은 public/assets/fonts/maruburi/OFL.txt에 있습니다.

### 비개발자를 위한 검사 결과 안내

결과 맨 위의 **첫 번째 항목 함께 고치기**에서 설명 읽기 → AI에 수정 부탁하기 → 수정 후 다시 확인하기의 3단계로 진행합니다. 코드 증거·배포 검토표·개발 담당자용 상세 정보는 접어서 표시합니다. 항목별 수정 부탁 문구는 발견 위치와 수정 지침, 파일이 없을 때 요청할 정보, 기능 보존과 확인 절차를 포함합니다. 편집 후 복사할 때도 알려진 비밀값을 마스킹하며, 복사만 수행하고 AI 전송·자동 수정은 하지 않습니다.

### 쉬운 설명 도우미

항목별 수정 안내 상단에 세 질문(왜 문제인지 / 어디에 붙여 넣는지 / 수정 후에도 나오는 이유)을 접어서 제공합니다. 규칙 종류에 맞는 일상 예시와 파일·주소·가상 API별 재검사 안내를 표시합니다. 준비된 설명이며 AI 채팅·외부 전송·별도 대화 저장은 없습니다.


### 비밀값 출력 보호 보강 (2026-10-21)

### 많은 탐지 결과 읽기
결과 목록은 같은 규칙의 위치를 묶어서 표시합니다. 테스트·예제 경로(tests, fixtures, demo-data, examples, samples 및 test/spec 파일)는 별도 펼침 영역으로 분류하지만 검사·보고서·재검사에서는 제외하지 않습니다. 경로 기반 분류는 안전 판정이 아닙니다. 일반 파일에도 예제나 탐지 규칙 문자열이 포함될 수 있어 사용 문맥을 확인해야 합니다. 이 저장소를 검사한 122곳은 일반 파일 35곳(11개 묶음), 테스트·예제 87곳(22개 묶음)이었습니다. 임원 현황판의 조치 집계는 기존 규칙·파일 단위를 유지합니다.


### 쉬운 결과 안내
결과 첫 화면은 회사 자료 노출, 다른 사람 자료 접근, 기타 보호 설정의 세 질문으로 구성합니다. 정적 패턴 발견은 ‘확인이 더 필요해요’, 미확인 범위는 ‘이번 검사로는 알 수 없어요’, 가상 API는 ‘연습 결과예요’로 표시합니다. 전체 횟수·위치와 필터는 담당자용 상세 영역에 유지합니다. 쉬운 안내는 대표 위치에서 시작하며 같은 종류의 다른 위치도 상세 목록에서 확인해야 합니다. 실제 서비스의 자료 접근 검증 기능을 추가한 것은 아닙니다.


### 발견 내용과 수정 안내
결과 화면은 질문 중심 안내 대신 실제 탐지에 따른 발견 내용, 확인된 사실과 한계, 조건별 변경 방법을 바로 표시합니다. 같은 조치 종류의 모든 위치를 포함한 요청문을 결과 카드에서 복사할 수 있습니다. 원문 증거는 복사하지 않으며 예시·테스트·탐지 규칙인지 먼저 검토하도록 요청합니다. 처음에는 개인정보·비밀값·접근 제한 등 앞선 세 종류를 표시하고, 나머지 조치와 예제 경로는 별도 펼침에 보관합니다. 이는 탐지 정확도 향상이나 실제 유출 검증을 뜻하지 않습니다.


### 수정 대상 판정 기준 (2026-10-21 갱신)
기존 발견 카드 안내를 대체합니다. 정규식 발견, 심각도, detected 분류만으로는 수정 대상으로 올리지 않습니다. 파일 검사는 현재 사용 경로·배포를 검증하지 않으므로 추가 확인 후보로 남깁니다. 예제/테스트 경로와 가상 API 결과도 기본 수정 목록에서 제외합니다.
