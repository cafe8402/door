## 1장 — AI로 만든 업무도구, 공개 전 한 번 더 확인

### 한 줄 메시지

**개발을 몰라도, 위험한 부분을 찾고 다음 행동까지 안내받는 첫 보안 점검.**

### 왜 필요한가

AI로 업무도구를 쉽게 만들 수 있게 됐지만, 화면이 잘 작동해도 비밀키 노출이나 느슨한 자료 접근 설정이 남을 수 있습니다. 비개발자에게는 ‘무엇을 고쳐야 하는지’와 ‘어떻게 부탁해야 하는지’까지 연결해 주는 안내가 필요합니다.

### 핵심 내용 — 화면에는 아래 3가지 중심으로 배치

1. **위험한 코드·설정 찾기**
   - 코드에 직접 적힌 비밀키, 외부 입력을 조회·실행 명령에 연결한 코드, 누구나 자료 변경을 허용한 저장소 규칙 등을 확인합니다.
2. **쉬운 말로 다음 행동 안내**
   - 수정할 항목과 추가 확인할 단서를 구분하고, AI에게 전달할 수정·확인 요청문을 제공합니다.
3. **원문은 브라우저 안에서 검사**
   - 파일·폴더 내용을 외부 AI로 자동 전송하지 않습니다. 사용자가 요청문을 복사해 자신이 사용하는 AI에 전달합니다.

### 추천 도식

**파일·폴더 선택 → 위험 단서 확인 → AI 요청문 복사 → 수정 후 재검사**

### 발표 멘트

“AI로 만드는 일은 쉬워졌지만, 안전하게 쓰는 방법까지 쉬워진 것은 아닙니다. 이 서비스는 비개발자가 업무도구의 위험한 부분을 이해하고, 만든 AI에게 수정을 요청한 뒤 다시 확인하도록 돕습니다.”

## 2장 — 발견에서 수정 확인까지, 세 단계로

### 한 줄 메시지

**경고만 보여주고 끝내지 않고, 무엇을 해야 하는지 한 단계씩 안내합니다.**

### 시연 흐름 — 3단계 카드로 표현

| 단계 | 사용자에게 보이는 안내 | 실제로 할 일 |
| --- | --- | --- |
| ① 문제 확인 | “수정 필요 · 1곳” + 짧은 문제 설명 | 발견한 파일과 위치 확인 |
| ② AI에게 수정 부탁 | “수정 요청문 복사” | 서비스를 만든 AI에 붙여 넣고 수정 요청 |
| ③ 다시 검사 | “고친 자료 다시 검사” | 수정한 파일·폴더 선택 후 결과 비교 |

추가 확인이 필요한 경우에는 **내용 보기 → AI에게 확인 부탁 → 답변 후 할 일**로 안내합니다. 직접 코드를 판단하기 어려운 사용자를 위해 확인 질문을 준비합니다.

### 대표 시연 사례

**상황:** 고객 검색창의 입력값을 자료 조회 명령에 그대로 붙이는 코드.

**수정 전: 수정 대상 1곳 → AI에 수정 요청 → 수정 후: 해당 단서 0곳**

- 변경 내용: 입력값과 자료 조회 명령을 분리해 전달하도록 수정.
- 검증: 실제 고객정보와 DB 연결 없이 만든 더미 코드로 수정 전후를 검사했습니다.

### 검증 결과 — 숫자 강조

**6가지 시연 유형 모두 수정 전 탐지·수정 후 해당 단서 미검출 확인**

비밀키 노출 2종 · 고객 검색 입력값 연결 · 서버 명령 실행 · 공개 자료 변경 권한 · 입력문 코드 실행

> 검증 범위: 합성 시연 파일의 정적 분석과 재검사 비교. 실제 공격이나 개인정보 유출을 재현한 결과가 아닙니다.

### 배포 현황 — 하단에 짧게 표시

- **ChatGPT Sites 비공개 배포 완료:** 파일·폴더 검사, 단계별 안내, 재검사 제공.
- **현재 범위:** 주소 검사는 준비 중. 실제 계정별 자료 접근 권한은 별도 검증이 필요합니다.
- **시연 주소:** https://ai-work-security-check.cafe8402.chatgpt.site
- 현재는 소유자 비공개이므로 발표자가 로그인한 화면으로 시연합니다. 링크만으로 청중이 접속할 수 있다는 안내는 하지 마세요.

### 발표 멘트

“고객 검색 코드로 시연하면 수정이 필요한 위치가 한 곳 표시됩니다. 준비된 요청문을 만든 AI에게 전달해 고친 뒤, 같은 파일을 다시 검사하면 해당 단서가 사라진 것을 비교할 수 있습니다. 여섯 가지 더미 유형에서 이 흐름을 검증했고, 현재 파일 검사 버전을 Sites에 비공개로 배포했습니다.”

## 제작 시 사실관계 주의

- ‘6개 유형 검증’은 모든 취약점 탐지 성능이나 실제 서비스 안전성을 보장하는 수치가 아닙니다.
- AI가 앱 내부에서 자동으로 코드를 고치는 기능은 없습니다. 요청문 복사 후 사용자가 별도 AI에 수정을 부탁합니다.
- 비밀키의 실제 유효성, 실제 개인정보 유출, 로그인 계정별 접근 권한까지 확인했다고 표현하지 마세요.
- 재검사에서 같은 단서를 찾지 못한 것을 ‘모든 보안 문제 해결’로 표시하지 마세요.
- 근거 없는 해킹 통계나 비용·시간 절감 수치를 추가하지 마세요.
