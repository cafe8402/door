# 시연용 파일 · 실제 서비스가 아닙니다

실제 개인정보와 발급받은 비밀키는 들어 있지 않습니다. 키 모양 문자열은 로컬에서 무작위로 만든 미발급 값입니다. 이 파일들은 검사에만 사용하고 실행·배포하지 마세요.

## 이렇게 시연하세요

1. 앱에서 **새 검사 시작 → 코드 파일 → 폴더 선택**을 누릅니다.
2. 아래 유형 중 하나의 **수정전 폴더 자체**를 선택합니다. 시연자료 전체를 한 번에 선택하지 마세요.
3. 검사 권한에 체크하고 시작합니다. 첫 화면에서 발견한 사실, 바꿀 내용, AI 요청문을 보여줍니다.
4. **다시 검사하기**에서 같은 유형의 **수정후 폴더 자체**를 선택합니다. 파일 이름과 상대 경로는 같습니다.
5. 같은 단서가 사라진 결과를 보여줍니다. 이는 전체 서비스의 안전 판정이 아닙니다.

|유형|보여줄 상황|수정후의 변화|
|---|---|---|
|01 화면 비밀키|방문자가 받는 화면 파일에 비밀키 형식의 값이 있음|화면이 서버 API를 호출하도록 변경|
|02 서버 비밀키|서버 파일에 비밀키를 직접 적음|서버 환경변수에서 읽음|
|03 고객 검색|검색어를 고객 조회 명령에 그대로 붙임|조회 명령과 검색값을 분리|
|04 서버 명령|사용자가 보낸 글을 서버 실행 명령으로 사용|허용된 작업 함수만 실행|
|05 자료 변경|로그인 없이 누구나 저장소 자료 변경 가능|로그인한 본인 경로만 허용|
|06 계산식|계산식 입력을 프로그램 코드로 실행|숫자와 정해진 연산만 처리|

## 추천 시연 순서

**03 고객 검색 → 05 자료 변경 → 01 화면 비밀키** 순서가 개인정보와 외부 접근 위험을 설명하기 좋습니다.

발표 문구: “가짜 업무 코드에서 위험한 작성 방식을 찾고, 바꿀 위치와 요청문을 제시합니다. 고친 파일을 다시 검사해 같은 단서가 사라졌는지 확인합니다.”

## 검사 범위

수정후 파일은 해당 문제를 설명하기 위한 최소 변경입니다. 실제 로그인·권한, 서버 API 구현, 키 교체, DB 연결이나 Firebase 배포까지 완료한 앱이 아닙니다. 실제 데이터 유출을 재현하거나 공격 요청을 보내지 않습니다.

`tests`, `examples`, `demo-data` 폴더 안에 묶어 선택하면 앱이 예제 기록으로 분리할 수 있습니다. 안내대로 각 수정전·수정후 폴더를 선택하세요. 탐지 규칙을 시연용으로 완화하지 않았습니다.
