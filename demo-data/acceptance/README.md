# 가상 직원 검색 도구 검증

검증일: 2026-10-21 (한국 시간)

이 폴더는 검사·수정·재검사 흐름을 검증하기 위한 합성 자료입니다. 실제 서비스, 계정, 개인정보, 외부 API 호출을 포함하지 않습니다. 실행 가능한 웹앱 전체가 아니며 staff.mjs의 함수만 가짜 DB·응답 객체로 실행 검증합니다. SQL 파일은 실제 DB에서 실행하지 마세요. 가짜 비밀키는 유효하지 않습니다. fixed는 검사 대상 패턴을 수정한 예시이며 운영 배포용 완성 코드가 아닙니다.

## 폴더

- before: config.mjs(가짜 키), staff.mjs(문자열 결합 SQL·전체 CORS 허용), policy.sql(행 접근 제한 비활성화). 기대 탐지 4건.
- partial: 키와 CORS는 수정, SQL 문제 유지, 동적 코드 실행 추가, policy.sql 누락. 기대 비교: 미검출 2 / 지속 1 / 확인 못함 1 / 신규 1.
- fixed: 키는 서버 설정에서 읽고 SQL은 매개변수로 전달, CORS는 예제 출처로 제한, SQL 정책은 사용자 기준으로 제한. 기대 탐지 0건.

## 화면에서 재현하기

1. 새 코드 파일 검사에서 before 안의 세 파일을 선택합니다. 검사 이름은 ‘검증용 · 가상 직원 검색’으로 입력합니다.
2. 검사 권한을 체크하고 검사를 시작합니다. 4개 항목을 확인합니다.
3. ‘첫 번째 항목 함께 고치기’에서 요청문에 config.mjs 위치가 있고 키 원문 대신 가림 표시가 있는지 확인합니다.
4. ‘수정 부탁 문구 복사’를 누릅니다. 외부 AI에 보내지 않아도 됩니다. 이 검증에서는 외부 AI를 호출하지 않았습니다.
5. 재검사에서 partial의 두 파일을 선택하고 같은 서비스임을 확인합니다. 미검출 2 / 지속 1 / 확인 못함 1 / 신규 1이 나와야 합니다.
6. ‘다시 수정해서 검사’로 돌아갑니다. 이전 두 파일을 각각 제거하고 fixed의 세 파일을 선택합니다. 미검출 4 / 나머지 0이 나와야 합니다.

일회성 검사로 진행했습니다. 업무시스템 관리에 연결해 등록하지 않았습니다. 이 목업은 기본 예제 버튼의 데이터가 아니므로 관리 현황에 연결하면 실제 검사로 집계될 수 있습니다. 시연 검증 자료를 실제 업무 지표에 섞지 마세요.

## 관찰된 개선점과 한계

1. 재검사에서 파일을 바꾸려면 기존 파일을 하나씩 제거해야 합니다. ‘수정본으로 전체 교체’ 동작과 안내를 추가하면 비개발자가 덜 헷갈립니다.
2. 초기 결과에서는 접어 둔 배포 검토표가 재검사 비교에서는 다시 크게 표시됩니다. 비교에서도 ‘달라진 점 → 다음 행동’을 먼저 보여주고 상세 표를 접는 편이 일관됩니다.
3. 반복 재검사의 비교 기준은 최초 검사입니다. partial에서만 새로 발견됐던 항목의 전체 이력 추적과는 다릅니다. 기준 검사 날짜·이름을 눈에 띄게 표시할 필요가 있습니다.
4. actual DB의 RLS, 네트워크 접근 권한, 키 폐기·교체는 실행 검증하지 않았습니다. fixed의 미검출은 운영 안전 인증이 아닙니다.
5. 다른 AI가 요청문을 받고 실제로 수정하는 과정이나 비개발자의 이해도는 검증하지 않았습니다. 수정본은 이 작업에서 직접 작성했습니다.
