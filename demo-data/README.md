# 문단속 더미 데이터 검증팩

총 18개 유형입니다. 실제 자격증명이나 개인정보는 포함하지 않습니다. 키는 DUMMY 반복 문자열, 주민번호 형식은 존재하지 않는 날짜, 개인키는 유효하지 않은 텍스트입니다. 파일은 실행하지 않고 문단속의 정적 검사 입력으로 사용하세요.

## 시작

1. ZIP 압축을 풉니다. ZIP 자체를 앱에 올리지 않습니다.
2. 문단속에서 새 검사를 시작하고, 원하는 유형의 before 폴더를 프로젝트 폴더로 선택합니다.
3. 검사 결과를 아래 표와 비교합니다.
4. 고친 뒤 다시 검사에서 같은 유형의 after 폴더를 프로젝트 폴더로 선택합니다.
5. 같은 상대 경로로 비교되므로 01~14는 각각 패턴 미검출 1건이 나와야 합니다.

01~14의 after는 해당 패턴 제거 예시이며, 완전한 서버 구현이나 기능 보존을 보증하지 않습니다. 한 번에 전체 demo-data 폴더를 올리면 before·after·설명 파일이 함께 스캔되므로 유형별 폴더를 선택하세요. 각 유형은 별도의 새 검사로 시작합니다.

| 폴더 | 유형 | 처음 | 수정 후 |
|---|---|---:|---:|
| 01-openai-key | OpenAI 키 | 1 | 0 |
| 02-anthropic-key | Anthropic 키 | 1 | 0 |
| 03-aws-key | AWS 키 ID | 1 | 0 |
| 04-browser-ai | 브라우저 AI 직접 호출 | 1 | 0 |
| 05-personal-data | 주민번호 형식 | 1 | 0 |
| 06-cors | CORS 전체 허용 | 1 | 0 |
| 07-dynamic-code | 동적 코드 실행 | 1 | 0 |
| 08-google-key | Google API 키 | 1 | 0 |
| 09-github-token | GitHub 토큰 | 1 | 0 |
| 10-private-key | 개인키 블록 | 1 | 0 |
| 11-shell-execution | 셸 실행 | 1 | 0 |
| 12-html-insertion | HTML 직접 삽입 | 1 | 0 |
| 13-tls-verification | TLS 검증 해제 | 1 | 0 |
| 14-agent-approval | 에이전트 승인 우회 | 1 | 0 |
| 15-mixed-rescan | 재검사 4개 상태 동시 검증 | 3 | 2 |
| 16-repeated-findings | 동일 규칙 여러 줄·파일 | 3 | 해당 없음 |
| 17-clean-and-empty | 정상 텍스트·빈 파일 | 0 | 해당 없음 |
| 18-scope-limit | 현재 규칙의 미탐 한계 | 0 | 해당 없음 |

## 추천 확인 순서

- 01-openai-key: 발견 위치·증거·AI 수정 요청문·보고서에서 DUMMY 키가 숨겨지는지 확인합니다.
- 05-personal-data: 가상 주민번호가 화면과 요청문에서 마스킹되는지 확인합니다.
- 06-cors: 여러 줄 설정도 탐지하는지 확인합니다.
- 15-mixed-rescan: before 검사 후 after 재검사 시 패턴 미검출 1, 문제 지속 1, 확인 불가 1, 새로 발견 1입니다. 현재 코드의 새 탐지 건수는 2건입니다.
- 16-repeated-findings: 폴더 전체를 최초 검사하면 a.js 2건, b.js 1건이며 상세 위치가 각각 달라야 합니다.
- 17-clean-and-empty: 최초 검사 시 2개 파일을 분석하고 탐지는 0건입니다.
- 18-scope-limit: 사용자별 인가 누락 예시지만 현재 엔진은 탐지하지 않습니다. 0건이 안전 보증을 의미하지 않는지 확인하는 한계 사례입니다.

발견한 문제와 문제일 수 있어요의 구분·위험도·규칙 ID는 expected-results.json에 있습니다. 정적 패턴이므로 주석·테스트 문자열도 검출될 수 있습니다.
